The path

Receiving always. Prep or Pack by route. Returns only if returned.

flow.json, flow_id standard-v1. A stage that does not apply is skipped and the reason is stored. A stage is never skipped because an agent was down. That is an error.

1 · ReceivingAlways. Dock identity, cartons, quantity, damage.
→
2 · Prep or PackPrep when route is FBA. Pack when route is merchant-fulfilled. Unknown route runs neither.
→
3 · ReturnsOnly when returned is true. Identity, completeness, condition. Policy chooses disposition.
→
4 · RecoveryAlways. Reads the evidence chain. Rules decide. The model does not rewrite history.
PolicyDefaultWhat it does
timeout30 secondsThen a retry.
retries1Transient failures retry. A 4xx refusal does not.
on_uncertaincontinueUNCERTAIN stays UNCERTAIN and travels forward. A person is asked when needs_human is true.
on_errorcontinueOther stages can still write evidence. The workflow still ends FAILED if a required stage never finished.

Every agent output is checked for schema, stage, workflow, tenant, and hash before it is stored. Evidence is append-only. A person’s disagreement is an override that names the record it supersedes.

What one run gives

A workflow, an evidence chain, and a derived outcome

The latest agent answer is not the source of truth. rollup.py derives status and final outcome from the stored records and overrides.

WF-…workflow_id from org and unit. Starting the same unit again advances it. It does not duplicate it.
EvidenceOne immutable record per attempt. Failed attempts stay. Retries add a new record.
OutcomeCLEAN, EXCEPTION, NEEDS_REVIEW, CLAIM_RECOMMENDED, or INCOMPLETE, with a reason and the record ids behind it.
Field on the finished workflowWhat you show
statusPENDING, IN_PROGRESS, COMPLETED, FAILED, BLOCKED, or RECOVERY_REQUIRED

How to read the result

Status says whether the bus finished. Outcome says what it found.

PASSRecord it. Continue.
FAILA finished judgment, not a crash. The bus keeps going.
UNCERTAINKept as written. Never turned into PASS.
If the evidence saysStatusFinal outcome
Every required stage passedCOMPLETEDCLEAN
A stage FAIL, and Recovery did not contradict a chargeCOMPLETEDEXCEPTION
A stage asks for a personBLOCKEDNEEDS_REVIEW
FAIL and a person is also waitingBLOCKEDEXCEPTION. The person comes first in the status.
Recovery verdict FAIL, earlier stages finishedCOMPLETEDCLAIM_RECOMMENDED. claimable_usd is set.
Recovery silent, needs_human falseCOMPLETED if the rest passedCLEAN. Silence is not a failure.
A required stage timed out, crashed, or refusedFAILEDINCOMPLETE. Resume retries the failed stage.

A claim is withheld when an earlier stage did not finish, even if Recovery’s own verdict was FAIL. That outcome becomes INCOMPLETE.

When an agent breaks

The judgment that already landed is kept. The process does not die.

BreakWhat is stored
Connection refusedFAILED / INCOMPLETE. Receiving UNCERTAIN, error agent_unavailable. Prep is not asked to invent that judgment.
Resume after the agent answersOn the injected case: COMPLETED / CLEAN. Receiving PASS. Attempts seen: 5.
Every agent raisesFAILED / INCOMPLETE. Four stages error / UNCERTAIN. The exception does not leave run_workflow.
